# Deployment

This fork starts from hybula/lookingglass commit `417381108bfb8e2a56343ccaaa3ad5b6742b2df5` and adds NextTrace plus a shared, read-only xterm.js terminal for every method.

## Docker

```sh
git clone https://github.com/SkywolfCloud/lookingglass.git
cd lookingglass
cp compose.skywolf.yaml compose.override.yaml
# Adjust the node details in compose.override.yaml for your deployment.
docker compose build
docker compose up -d --wait
```

`compose.skywolf.yaml` contains the public Skywolf Hong Kong node configuration. The local `compose.override.yaml` is ignored by Git. The base Compose file has generic defaults and can run without an override. Images are built locally; no prebuilt `skywolfcloud` images are required or published.

Nginx listens on port 80 for IPv4 and IPv6. PHP-FPM listens only on `127.0.0.1:9000`; the containers use the host network so probes follow the host's routes. The Docker build supports Linux amd64 and arm64 and pins NextTrace v1.7.5 with a separate SHA256 for each architecture. The PHP image gives only the NextTrace executable `cap_net_raw`; the containers do not need privileged mode or NET_ADMIN.

All eight methods use the same fixed dark terminal even when the page is light. MTR refreshes the table using cursor control sequences. Ping, Traceroute and NextTrace stream text directly. The frontend consumes bytes with xterm.js, supports resizing and text selection, and sends no terminal keyboard input to the server. It exposes no interactive shell, PTY or websocket.

NextTrace uses its default realtime formatter with TERM=xterm-256color and COLORTERM=truecolor. Native ANSI styles are rendered with the standard xterm.js palette, without palette overrides or contrast-based color substitution. It is bounded to 45 seconds, 30 hops and two probes per hop; its geolocation/ASN data uses the default NextTrace API. Other commands have a 60-second overall limit. The NextTrace generic capability notice is suppressed after a trace starts; failures before tracing remain visible. Session cookies use Secure when PHP sees HTTPS and work with the existing HTTP endpoint. If terminating TLS at a reverse proxy, configure trusted HTTPS forwarding on the web server.

The logo and favicon are served locally; the logo links to https://hk.skywolf.cloud/. xterm.js 6.0.0 and addon-fit 0.11.0 are vendored with their MIT licenses, with npm SHA512 integrity checked when downloaded. See [third-party notices](brand/THIRD_PARTY.md).

## Operations

```sh
docker compose ps
docker compose logs --tail=100
docker compose build && docker compose up -d --wait
```

Before updating a live installation, back up the source and local override and retain the current image tags for rollback. Do not overwrite a local override with the example during upgrades. IPv6 methods require IPv6 connectivity from the host.

## Validation

Run PHP syntax checks and `node --check brand/terminal.js` for local edits. Against a running deployment, `python3 tests/http_smoke.py http://127.0.0.1/` exercises all eight methods, verifies the plain-text stream and MTR refreshes, checks single-use backend requests, and rejects invalid targets and CSRF tokens. It probes public Cloudflare IPv4 and IPv6 endpoints.

## Speed-test service

The Compose stack runs the official ALS backend at `127.0.0.1:19080`, pinned to multi-architecture digest `sha256:a04ad6948c7246497490d2ce724b0488a30454e1b63c64c7d8406b85a4ed9892`. Nginx proxies only its speed-test session, worker, transfer, traffic and selected utility APIs under `/als/`; its shell and separate diagnostic methods are not exposed. PHP workers are not used for speed-test transfers or event streams.

- Browser tests use the ALS-embedded LibreSpeed worker for ten-second download and upload phases, plus HTTP latency and jitter. Telemetry is disabled. A stop button cancels the worker and its transfers.
- Test files (1MB, 10MB, 100MB and 1GB by default) are generated by ALS; they do not consume disk space. Downloads can use the current host or direct IPv4/IPv6 on HTTP.
- Traffic graphs derive Mbps from byte-counter differences and their actual timestamps. They describe total interface traffic, including other services.
- Server tests use the image's Ookla Speedtest CLI, display progress and a share-result link, accept an optional numeric server ID, and participate in the ALS queue. They measure the node's network, not the visitor's connection.
- iPerf3 is started only on request, using a random TCP/UDP port in `5201–5210`. A detached, bounded PHP CLI worker owns its ALS control session for sixty seconds, independent of browser fetch/SSE connections. Short session-scoped `iperf.php` start/status/stop requests use a stable CSRF token; page refreshes recover the current job. Switching applications or closing the page does not stop it; explicit Stop or the server-side timeout does. Permit this range in the host/provider firewall if clients need to connect from outside. The UI supplies IPv4/IPv6 commands for both directions and displays a read-only terminal log.

The settings are in the `speed-backend.environment` section of Compose. `ENABLE_SPEEDTEST`, `DISPLAY_TRAFFIC`, `UTILITIES_SPEEDTESTDOTNET` and `UTILITIES_IPERF3` control their respective features. `SPEEDTEST_FILE_LIST` selects sizes; `UTILITIES_IPERF3_PORT_MIN/MAX` select the iPerf port range (also update firewall policy when changing it). The Skywolf override supplies node IPs and location to both backends. If a local override previously set `DISABLE_BLOCK_SPEEDTEST=true`, remove that entry to enable the panel. The legacy static test-file and iPerf command configuration remains available under Other test endpoints.

For isolated testing, run `python3 tests/prepare_stage.py`, then `docker compose -p lg-stage -f docker-compose.yml -f compose.skywolf.yaml -f tests/compose.stage.yaml up -d --build --wait`. This uses separate container names, loopback web port 18080, PHP-FPM 9001, ALS API 19081 and iPerf3 ports 5221–5230. Run `python3 tests/speed_smoke.py http://127.0.0.1:18080/` for small transfer, session, route and traffic checks; `--iperf --backend-container lg-speed-backend-stage` adds a rate-limited one-second local iPerf transfer and cancellation test. `--server-test` performs a real external Speedtest.net test and can transfer substantial data. Run it only when validating that integration. python3 tests/iperf_lifecycle.py http://127.0.0.1:18080/ --full-lifetime verifies that a page/SSE disconnect and refresh do not stop the server, completes a rate-limited transfer, and checks the full sixty-second expiry and port release. Without --full-lifetime, it checks explicit Stop instead.

A page maintains one ALS event stream for browser transfers, traffic and Speedtest.net; disconnecting it cancels those backend tasks, so keep the page open for test-file downloads. iPerf3 has its own worker-owned control session and remains available for its sixty-second lease even when the page disconnects. Only one active speed-test action is allowed per page. Existing diagnostic methods remain available.
